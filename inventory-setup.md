# Daily inventory setup

1. Review and run `inventory-schema.sql` once in the Supabase SQL editor for the existing project. This migration creates only new inventory tables, RLS policies and a function; it is **not** executed automatically. Back up your database first. Rollback, if required: drop function `public.inventory_save_import(date,text,jsonb,text)`, then drop tables `inventory_imports`, `inventory_mappings`, `inventory_entries`, `inventory_items` in that order (this deletes inventory data).
2. Serve the site as usual over HTTPS (or localhost for development), sign in, and open `inventory.html`. The captain will integrate navigation and service worker caching separately. Schema and user session are required.
3. Add stock items with a start date and initial count. For each date, save purchase and damage separately per item. Sale comes from a POS report. Closing is opening + purchase − sale − damage; gaps carry the last balance forward. Counts before an item's start date are not available. A negative closing is shown as a shortage, not blocked. Editing an initial count, an earlier movement or an earlier imported sale recalculates all later openings on the next read; no derived balances are persisted. Start dates cannot be edited after creation.
4. Upload an `.xls` or `.xlsx` report locally. The **first sheet** must have a single unambiguous date before a `Category / Item / Code / Qty. / Total` header, using DD/MM/YYYY or YYYY-MM-DD (also accepts dots and hyphens). Ranges with different dates are rejected. Category-only rows and total/subtotal rows are excluded. Item rows must have a non-negative numeric quantity. The importer uses quantity as plates and a bracketed count such as `[3 Pieces]` or `(1 Piece)` as pieces per plate, defaulting to one, including thali. Check the displayed dishes and totals carefully against the original report before confirming. Other report layouts or date formats may need conversion first; unsupported layouts are rejected rather than guessed.
5. Choose an item or **Ignore** for every distinct category + item name + code. Names and categories distinguish reused codes. Existing saved mappings and **Ignore** choices always take precedence and remain editable. For unmapped dishes, the importer suggests a stock item only when normalized whole-word matching on the dish item name (accounting for case, punctuation, whitespace, and piece annotations such as `[3 Pieces]`, while avoiding substring false positives) identifies exactly one candidate; suggestions show the matched item and reason and must be explicitly reviewed/accepted before previewing or importing. Ambiguous multi-candidate matches are never auto-mapped and list candidates for manual selection. Multiple dishes may map to one item. Choices are saved per user on confirmation and can be edited on the next report. Past imports are snapshots, so changing a mapping does not rewrite past sales; reimport that day to replace them. Mapping preferences may save even if the subsequent import fails; errors are displayed.
6. The report date must match the selected date. The preview shows totals and warns before replacing an existing day's entire import. The same normalized report and choices are detected as a duplicate. A changed report or mapping requires explicit replacement. Concurrent changes to the day's import cause an error instead of silently overwriting another user's tab; preview again. A replacement can contain zero sales when every dish is ignored.

## Privacy and limitations

The browser loads the vendored, pinned SheetJS Community Edition `0.20.3` reader from `js/vendor/xlsx.full.min.js` (Apache-2.0) to parse `.xls` and `.xlsx` files locally in the browser; raw workbooks are never sent to any server, though mapped aggregate sales and mapping choices are saved to Supabase.

- **Dependency origin and integrity verification:** Official SheetJS CE `0.20.3` standalone browser build (`https://cdn.sheetjs.com/xlsx-0.20.3/package/dist/xlsx.full.min.js`, upstream tag `v0.20.3` / commit `8a7cfd47bde8258c0d91df6a737bf0136699cdf8` at `https://git.sheetjs.com/sheetjs/sheetjs/tags.rss`, released `2024-07-18`). `0.20.3` resolves the published `0.18.5` CVEs (`CVE-2023-30533` fixed in `0.19.3`, `CVE-2024-22363` fixed in `0.20.2`) and remains the latest official SheetJS CE release listed at `https://cdn.sheetjs.com/` and `https://sheetjs.com/`. Checksums for the vendored `951,904`-byte file:
  - Official SheetJS MD5 (published at `https://docs.sheetjs.com/docs/miscellany/contributing/`): `6b3130af1ceadf07caa0ec08af7addff`
  - SHA-256: `cc015130aa8521e7f088f88898eba949ccdcbfb38df0bd129b44b7273c3a6f41`
  - Upstream source tarball (`xlsx-0.20.3.tgz`) SHA-512 SRI: `sha512-oLDq3jw7AcLqKWH2AhCpVTZl8mf6X2YReP+Neh0SJUzV/BdZYjth94tG5toiMB1PPrYtxOCfaoUCkvtuH+3AJA==`
  - In the build sandbox (where shell egress is limited to GitHub/npm/PyPI), package metadata, license, changelog, and bundle boundary snippets were checked directly against `cdn.sheetjs.com` and `docs.sheetjs.com`, and identical bytes (`MD5 6b3130af1ceadf07caa0ec08af7addff`, `SHA-256 cc015130...`) were cross-verified across independent mirrors before vendoring. Maintainers with unrestricted egress can verify directly via `curl -sSL https://cdn.sheetjs.com/xlsx-0.20.3/package/dist/xlsx.full.min.js | sha256sum`.
- **Operational limits:** Only import trusted POS report workbooks (`0.20.3` has had no newer upstream CE release since `2024-07-18`, and files are capped at 10 MB client-side). The existing Supabase JS library and site assets also require their configured networks. Web Crypto (HTTPS or localhost) is needed for duplicate fingerprints. Data is read from Supabase on page load and after saves; offline use and continuous cross-tab updates are not supported. Refresh before making decisions if another device is editing stock. Import replacement is atomic and checks for concurrent replacement; ordinary item and movement edits are last-write-wins. Browser arithmetic uses JavaScript numbers; display is rounded to four decimal places, while stored movements retain entered precision. No real sales data or credentials are included.

Run the focused checks with `python3 -m pytest -q tests/test_inventory.py` (Node.js required). These test synthetic rows and pure logic, plus the vendored SheetJS `0.20.3` reader on synthetic `.xls`/`.xlsx` fixtures, not live Supabase policies.
