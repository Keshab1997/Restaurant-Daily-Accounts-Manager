# stock-sheet — Worker A

**Repository:** `Keshab1997/Restaurant-Daily-Accounts-Manager` — attach this repo in Arena Agent Mode.

**Goal and acceptance:** Implement an authenticated, mobile-friendly daily inventory page matching the app style. Show item, opening, purchase, sale, closing, damage in pieces by date. Closing = opening + purchase − sale − damage; the previous day's closing supplies opening, with a user-entered initial opening when no previous day exists. Allow stock items to be added/edited and purchase/damage entered. Save per user in Supabase, provide an explicit migration SQL including ownership RLS; do not execute it. Handle editing earlier days safely: later derived opening/closing values must not silently go stale.

Import the restaurant POS item report from a locally uploaded `.xls` or `.xlsx` (the source report contains a date line, Category/Item/Code/Qty./Total header, category and subtotal rows). Extract only actual item rows, ignore totals and category rows, use Qty as plates, parse `[3 Pieces]`, `(1 Piece)` etc.; default to one piece when absent, including thali. Multiply Qty by the piece count. Map each sold dish to one stock item via editable, persisted per-user dish mapping; allow many dishes per item. Show unmapped/ambiguous dishes for user confirmation rather than guessing, then preview item totals and confirm before saving. Prevent duplicate counting when importing the same report/day again, and support replacing that day's imported sale safely. Do not use code alone as a unique identifier: the report can reuse codes for different items. Use the report date and flag a mismatch with the selected day before saving. Do not assume every POS item belongs in stock: allow explicit ignore. Do not publish real sales data or credentials.

Page path is `inventory.html`; Captain will add navigation and service worker integration later. Use a pinned well-known browser XLS reader if needed; disclose its source and behavior, no server upload. Include focused automated tests in the assigned test file exercising report parsing, pieces, mapping, duplicate import and stock arithmetic (including changed earlier-day behavior); no real data. No new package manifests or generated files.
